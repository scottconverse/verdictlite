v0.1.11 · early release · Apache-2.0

Make the coding agent run the checks before it stops.

VerdictLite is a small command-line tool for git repos. When a Claude Code agent tries to stop, it runs your checks. It flags tests that were skipped or deleted. At commit time it writes down how the change was verified.

The problem

Agents say "done" too early.

An AI coding agent can stop or commit without running the tests. When a test fails, it can be tempted to skip it, add a sleep, add retries or delete it. VerdictLite puts a simple check at each of those points.

What goes wrongThe agent stops without running the checks.

What VerdictLite doesA Claude Code Stop hook runs your checks for the parts of the repo that changed. If one fails, the stop is blocked and the agent gets the error.

What goes wrongA failing test gets skipped, slowed, retried or deleted.

What VerdictLite doesA built-in test-tamper check looks at the changed lines in test files. It flags added skips, fixed sleeps, retries and removed tests.

What goes wrongThe agent tries the same broken fix forever.

What VerdictLite doesRounds are counted. After three failed rounds the session ends and a person is asked to look, with a hand-off file of the full output.

What goes wrongA commit gives no sign of how it was checked.

What VerdictLite doesGit hooks add a Verified-By: line to every commit message: verify, code-review, stop-check, docs, skipped or none.

What goes wrongA change loosens the rules that judge it.

What VerdictLite doesThe config and the review rules are read from the base branch, not from the change. The tool and its logs live outside the repo.

How it works

Two gates: one when the agent stops, one when it commits.

The stop gate needs Claude Code. The commit gate is plain git hooks, so it works with any agent and with people.

What it does

Five commands. One config file.

Stop check

vlite stop-check runs the checks for each part of the repo that changed. A docs-only change passes at once. The same tree is never checked twice on one branch.

Three-round hand-off

Failed stops are counted per session. Rounds 1 and 2 block. Round 3 ends the session and points a person to a file with up to 2,000 lines of output.

Required orgs

vlite require-org NAME says that every repo of a GitHub org must have a vlite.json. The global Stop hook blocks once when a repo of that org has none.

Test-tamper check

Flags added skips, fixed sleeps, retries and removed tests in your test files. A test you remove on purpose is written down in TEST-REMOVALS.md.

Stamps

vlite stamp verify records that a check ran on the exact tree, with evidence files that must exist. The commit gate looks for it.

Commit gate

vlite install adds pre-commit and commit-msg hooks. They add a Verified-By: trailer. Modes are off, observe and enforce.

AI review

vlite review sends the diff and your REVIEW.md rules from the base branch to a review command (by default claude -p). A clean result writes a stamp.

Commit gate modes

Watch first. Enforce when the numbers say so.

Set gate.mode in vlite.json on the base branch.

  • off

    Nothing. No trailer, no log.

  • default

    observe

    Never blocks. Adds the trailer. Logs the commits that would have been blocked.

  • enforce

    Blocks a commit with method none. A Verify-Skip: line skips on purpose, with a reason.

Quick start

Install in one click, then set up one repo.

On Windows, download install-verdictlite.cmd from the latest release and double-click it. Or run the one line below in PowerShell. It needs no admin rights. It installs Node.js 20 with winget if you have none, checks the download’s SHA-256, and puts the files in %LOCALAPPDATA%\VerdictLite. The installer also connects VerdictLite to the Claude Code and Codex desktop apps. To update, run it again. To uninstall, delete that folder and remove its bin folder from your user PATH. On other systems, or to build it yourself, use the source steps further down: you need git, Node.js 20 or newer and pnpm. VerdictLite is not on npm.

  1. Install the tool

    PS> irm https://github.com/scottconverse/verdictlite/releases/latest/download/install.ps1 | iex

    Then restart the Claude and Codex apps. Codex runs a new hook only after you approve it: in Codex, click Review hooks, or open Settings > Hooks. To connect or disconnect later, run vlite connect or vlite connect --uninstall. Codex limit: VerdictLite checks only the repo that the Codex session opened in. It cannot read the Codex log to find other repos that the session changed.

    Open a new terminal and run vlite --help to check.

    From source (any OS). Keep the clone outside the repos it checks.

    git clone https://github.com/scottconverse/verdictlite.git
cd verdictlite
pnpm install
pnpm build
npm link

    npm link puts vlite on your PATH. Run vlite --help to check.

  2. Write vlite.json and merge it to the base branch

    {
  "version": 1,
  "base": "origin/main",
  "docs": ["**/*.md", "docs/**"],
  "parts": [
    { "name": "app", "paths": ["src/**", "test/**"],
      "checks": [ { "name": "tests", "run": "pnpm test" } ] }
  ],
  "tests": { "paths": ["test/**"] },
  "gate": { "mode": "observe" }
}

    The config is read from the base branch. Until it is merged there, VerdictLite uses your working copy and prints a warning each time.

  3. Install the git hooks

    $ vlite install --claude

    This adds the pre-commit and commit-msg hooks and prints the Stop hook settings. It keeps any hook you already have and runs it first.

  4. Add the Stop hook to .claude/settings.json

    {
  "hooks": {
    "Stop": [
      { "hooks": [
        { "type": "command", "command": "vlite stop-check", "timeout": 3600 }
      ] }
    ]
  }
}

    The timeout is in seconds. Make it longer than all your checks put together. Then add a verify skill so the agent stamps its work. The manual has a full example.

The five commands

vlite installAdds or removes (--uninstall) the git hooks. --claude prints the Stop hook settings.
vlite stop-checkThe Claude Code Stop hook. Runs the checks and the tamper check. Add --session NAME to run it by hand.
vlite stampRecords a verify or code-review result for the current tree, with evidence files.
vlite gateRun by the git hooks. vlite gate report shows what the gate saw.
vlite reviewOne AI review round against REVIEW.md from the base branch.

Honest limits

What it does not do.

Status: early

Version 0.1.11 is the eleventh fix to the first release (0.1.0), built on 2026-11-19. It has 192 automated tests (2 run on Windows only); the rest run on Ubuntu and Windows in CI. It is being set up on its first real repo now. Expect changes.

Found a problem? Open an issue.

  • It does not prove your code is right. It shows that your checks ran on this exact set of files. The checks are only as good as the ones you write.
  • A stamp is a speed bump, not proof. Anyone can write one by hand, and git commit --no-verify skips git hooks. VerdictLite makes these choices visible in logs and trailers. It does not make them impossible.
  • The stop check needs Claude Code. It uses the Claude Code Stop hook. Other agents get the commit gate only. The tamper check runs inside the stop check.
  • The tamper check is simple. It uses regular expressions. It can miss things and can flag lines that are fine.
  • If the tool itself breaks, it lets the agent stop. A failing check always blocks. A crash in VerdictLite does not; it logs an error instead.
  • The config must be on origin/main or main. A default branch with another name, such as master, is not searched in 0.1.11.
  • vlite review sends your diff to the review command you set, by default the claude CLI. The other commands run only on your machine.

Where the idea comes from

Built from a published method.

VerdictLite follows the steps in How the Claude Code team thinks about verification by Addy Osmani (November 16, 2026). It turns them into a stop check, a tamper check, stamps and a commit gate you can run today.
